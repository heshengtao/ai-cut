# 域：分镜与素材（storyboard）

分镜是把「想法」变成「可生成、可拍摄、可剪辑、可验收」的中间层。**每个镜头只回答一件事。**

## 1. 从 brief 到一句话承诺

先写一句全片承诺：

> 看完这条片子，观众会知道 **<产品/主题>** 能帮 **<谁>** 解决 **<什么问题>**，并且愿意 **<行动>**。

如果这句话写不出来，不要进入分镜。

## 2. 剧本格式（双栏 A/V）

```md
| # | 画面（Visual） | 声音（Audio） |
| --- | --- | --- |
| 1 | 产品结果特写，手入镜按下按钮 | VO：还在用 3 个工具拼一条视频？ |
| 2 | 旧流程屏幕，红叉逐个出现 | SFX：error beep；BGM 低频进入 |
| 3 | 新流程一屏完成，光标点击 | VO：现在，一句话。 |
```

规则：

- 先写声音再看画面：旁白决定节奏。
- 一句旁白只承载一个信息。
- 画面写「观众看到什么」，不要写「高级感」「科技感」。
- 屏幕文字单独一列，不要混进旁白。

## 3. 时长与语速

| 语言 | 舒适语速 | 快节奏 | 备注 |
| --- | --- | --- | --- |
| 中文 | 3.5–4.5 字/秒 | 5–5.5 字/秒 | 含标点停顿；新闻口播偏快 |
| 英文 | 2.3–2.8 词/秒 | 3–3.3 词/秒 | 约 140–170 wpm |
| 日文 | 4–5 假名/秒 | — | 以实际 TTS 试听为准 |

**镜头时长 = 旁白字数 / 语速 + 呼吸余量（0.3–0.8s）**

经验值：

- 钩子：1.5–3s
- 信息镜头：2–5s
- 口播 A-roll：5–10s（必须有画面变化）
- 标题/CTA：2–4s
- 一个段落：15–30s
- 社媒短片：总长 15–60s；长视频每 30–60s 一个章节

**不要先写 60 个镜头再配音。** 先定总时长与段落，再分配镜头。

## 4. 分镜表（storyboard.csv）

CSV 列：

```csv
shot,scene,duration_s,picture,shot_size,camera,action,vo,on_screen_text,audio,source,prompt_ref,acceptance
S01,钩子,2.5,"产品结果特写，手按下按钮","CU","微推","按钮亮起，界面弹出结果","还在用三个工具拼一条视频？","3 个工具 → 1 句话","hit + 低频 whoosh","gen-image→gen-video","prompts.md#S01","结果可读，手指自然，无变形"
S02,问题,3.0,"旧流程屏幕，红叉出现","MS","固定","三个窗口依次报错","剪辑、字幕、配音，各卡一次","Error ×3","error beep ×3","screen capture","—","红叉与旁白同步"
```

列说明：

| 列 | 写什么 |
| --- | --- |
| `shot` | 唯一编号，和素材文件名一致 |
| `scene` | 段落/章节 |
| `duration_s` | 预估秒数 |
| `picture` | 观众看到的具体画面 |
| `shot_size` | ECU/CU/MS/WS/EWS（特写/近景/中景/全景/大远景） |
| `camera` | 固定/推/拉/摇/移/跟/升降/手持/航拍 |
| `action` | 主体动作与变化 |
| `vo` | 旁白/对白原文 |
| `on_screen_text` | 屏幕文字，控制字数 |
| `audio` | BGM/SFX/环境声 |
| `source` | footage/screen/code/image/gen-video/stock |
| `prompt_ref` | 提示词文件锚点 |
| `acceptance` | 这个镜头怎样算过 |

## 5. 镜头语法

| 目的 | 景别 | 运镜 | 时长 |
| --- | --- | --- | --- |
| 建立环境 | WS/EWS | 缓慢推/航拍 | 3–6s |
| 建立人物 | MS | 固定/轻移 | 2–4s |
| 情绪/细节 | CU/ECU | 微推/固定 | 1–3s |
| 信息/UI | MS/CU | 固定 + 局部放大 | 3–8s |
| 转场 | 特写/遮挡 | 甩/遮挡/匹配剪辑 | 0.3–1s |
| CTA | 图形/logo | 定格/轻微缩放 | 2–4s |

**剪辑点优先选：** 动作中、视线转移、声音重音、构图匹配、方向一致。不要为了「卡点」牺牲语义。

## 6. 视觉连续性

- **角色设定板**：正面/侧面/3/4 侧、服装、发型、年龄、表情。
- **风格 token**：镜头（35mm/50mm/85mm）、光线（soft key / rim / golden hour）、色调（teal-orange / pastel / monochrome）、材质（film grain / clean digital）。
- **固定 seed / reference image / 模型版本**；记录在 manifest。
- **屏幕方向**：人物视线与运动方向跨镜头保持一致。
- **色板**：主色 1 + 辅色 1 + 强调色 1；避免每镜换风格。
- **字体**：标题/字幕/数据各一套，最多两套字重。

## 7. 生成式素材提示词

### 7.1 关键帧（图像）

模板：

```text
<主体与数量>，<动作/状态>，<环境/背景>，<景别与构图>，<镜头/焦距>，<光线>，<色彩与材质>，<风格>，<画幅>，<一致性 token>
```

示例：

```text
一位 30 岁亚洲女性产品经理，坐在明亮的开放式办公室，侧身看向笔记本屏幕，中近景，50mm，柔和窗光 + 右侧轮廓光，低饱和蓝灰配色，干净现代，电影感，16:9，角色设定：短发、米色西装、银色手表
```

负面约束：

```text
多余手指、畸形手、脸部变形、文字乱码、水印、logo、过度锐化、塑料皮肤、重复人物、错误透视
```

### 7.2 图生视频

模板：

```text
<首帧参考>，<主体动作>，<镜头运动>，<速度/节奏>，<光线变化>，<环境动态>，<风格>，<时长>
```

示例：

```text
以首帧为参考，女性缓慢转头看向镜头并微笑，镜头轻微推近，节奏自然，窗光保持稳定，背景有轻微景深流动，电影感，5 秒
```

规则：

- 动作要小、可完成；不要在一个 5 秒镜头里安排三个动作。
- 镜头运动只选一个：推、拉、摇、移、跟。
- 先出关键帧，再图生视频；纯文生视频只用于概念探索。
- 每镜 2–4 个 take；按「构图 / 动作 / 一致性 / 伪影」四项打分。
- 生成片段通常有压缩/闪烁，进 AI Cut 后做去闪烁、稳定、补帧。

### 7.3 代码动效（HyperFrames/Remotion）

- 先定「一帧长什么样」，再定「怎么动」。
- 动画只改变必要属性：位置、缩放、透明度、颜色、遮罩。
- 所有时间用帧/秒的纯函数；不要用 `Date.now()`。
- 文字先排版再动画；避免逐字抖动导致不可读。
- 转场优先「切 + 声音」，少用花哨 shader。

## 8. 字幕规格

| 项 | 建议 |
| --- | --- |
| 中文每行 | ≤ 16–18 字 |
| 英文每行 | ≤ 32–42 字符 |
| 最多行数 | 2 行 |
| 单条时长 | 1–6 秒；最短 0.8 秒 |
| 阅读速度 | 中文 ≤ 5 字/秒；英文 ≤ 17 CPS |
| 位置 | 底部安全区上方；避开平台 UI（底部 15%） |
| 对齐 | 居中；左对齐仅用于长段引用 |
| 字号（1080p 基准） | 44–64 px；标题 72–120 px |
| 对比 | 描边/阴影/半透明底；不要只靠颜色 |
| 标点 | 中文全角；英文半角；句末不强制句号 |
| 数字/单位 | 统一格式；价格/日期要准确 |

**断句原则**：按语义断，不按字数硬切；不要把「不」和动词分开；专有名词不拆。

## 9. 声音设计

| 层 | 作用 | 电平/处理 |
| --- | --- | --- |
| 旁白/对白 | 信息主载体 | 最清楚；峰值 -6 dBFS；压缩 2:1–3:1 |
| 音乐 | 情绪与节奏 | 比对白低 12–18 dB；旁白处 ducking 6–12 dB |
| SFX | 动作/转场/强调 | 短、准、不抢；峰值接近对白但更短 |
| 环境声 | 空间感 | 低电平铺底；避免与对白同频段 |

**卡点**：先测 BPM，再把关键剪辑点放在强拍/小节线；不要每个鼓点都切。

## 10. 素材清单（manifest）与命名

命名：

```text
<project>_<scene>_<shot>_<take>_<date>.<ext>
demo_s03_c01_take2_20261021.mp4
```

目录：

```text
assets/
  footage/      实拍
  screen/       录屏
  images/       关键帧/设计稿
  gen/          生成视频
  audio/        VO/BGM/SFX
  renders/      代码渲染输出
```

`manifest.json` 最少字段见 `pipeline.md`。**每个文件都要能回答：从哪来、能不能商用、对应哪个镜头。**

## 11. 交接给 AI Cut

分镜阶段就确定时间线映射，避免剪辑时再猜：

| 分镜字段 | AI Cut |
| --- | --- |
| `shot` | 素材名 / 片段 label |
| `duration_s` | `clip.duration` |
| `source` | 导入的 asset |
| `vo` | 字幕文字片段 / TTS 文本 |
| `on_screen_text` | 文字片段 `text` |
| `audio` | 音乐/SFX 轨 |
| `acceptance` | 审片清单 |

轨道规划：

- A-roll 放主叙事；B-roll 放上层；包装再上层；字幕置顶。
- 旁白/音乐/SFX 分轨，方便单独调电平。
- 每个段落留 0.3–0.5s 呼吸；不要在时间线里留大段空白。

## 12. 分镜自检

- [ ] 3 秒内能看懂「这条片子讲什么」吗？
- [ ] 每个镜头只有一个信息吗？
- [ ] 旁白念出来时长和镜头时长匹配吗？
- [ ] 每个镜头都有明确的来源与验收点吗？
- [ ] 屏幕文字在手机上看得到吗？
- [ ] 有没有「生成不出来」的镜头？兜底是什么？
- [ ] 音乐/音效有版权吗？
- [ ] 结尾有明确 CTA 吗？
