# 多语言（i18n）

AI Cut 的界面文案与 README 都支持 10 门语言：

| 语言 | id | 词典 | README |
| --- | --- | --- | --- |
| 简体中文（兜底） | `zh` | `src/i18n/zh.ts` | `README_zh.md` |
| 繁體中文 | `zh-TW` | `src/i18n/zh-TW.ts` | `README_zh-TW.md` |
| English | `en` | `src/i18n/en.ts` | `README.md` |
| 日本語 | `ja` | `src/i18n/ja.ts` | `README_ja.md` |
| 한국어 | `ko` | `src/i18n/ko.ts` | `README_ko.md` |
| Español | `es` | `src/i18n/es.ts` | `README_es.md` |
| Français | `fr` | `src/i18n/fr.ts` | `README_fr.md` |
| Deutsch | `de` | `src/i18n/de.ts` | `README_de.md` |
| Русский | `ru` | `src/i18n/ru.ts` | `README_ru.md` |
| العربية（RTL） | `ar` | `src/i18n/ar.ts` | `README_ar.md` |

## 运行时怎么工作

- `src/i18n/locales.json` 是**语言清单的唯一来源**：id、母语名、英文名、书写方向、对应的 README。
  界面语言选择器、README 导航、`scripts/i18n.mjs` 都读它。
- `src/i18n/translate.ts` 是纯查表（不依赖 Vue / DOM），无头文档引擎（QuickJS）也复用它。
  查表顺序：**当前语言 → 英文 → 兜底语言（简中） → key 本身**；
  `zh-TW` 缺词条时先看 `zh`，插件词典（`@<pluginId>.<key>`）走同样的回退链。
- `src/i18n/index.ts` 负责响应式语言状态、`localStorage`（`ai-cut-locale`）、
  `<html lang>` 和 `<html dir>`。语言判定顺序：用户选过的 → `navigator.languages` → 兜底。
  `zh-Hant / zh-TW / zh-HK / zh-MO` 落 `zh-TW`，其余 `zh-*` 落 `zh`。
- 阿拉伯语整页 `dir="rtl"`：主界面靠 flex 顺序自动翻转；**时间线与预览舞台固定 `dir="ltr"`**
  （时间轴方向和画面坐标是剪辑的肌肉记忆，不随语言翻转）。

## 加一条界面文案

1. 在 `src/i18n/en.ts` 和 `src/i18n/zh.ts` 里各加一条（key 用小写点分，按现有命名空间分组）。
2. 其余 8 门语言由翻译流程补齐（见下）。**不要**在组件里写死中文/英文。
3. `pnpm test` 会检查所有词典的 key 集合、key 顺序、空值、`{placeholder}` 是否一致。

## 加一门语言

1. `src/i18n/locales.json` 加一条（`id` / `label` / `english` / `dir` / `readme`）。
2. 复制一份词典到 `src/i18n/<id>.ts`，在 `translate.ts` 的 `MESSAGES` 和 `Locale` 联合类型里登记。
3. `README_<id>.md` 翻译一份，再跑 `node scripts/readme-nav.mjs` 重写所有 README 的语言导航。
4. `pnpm i18n:check` 必须是全绿。

## 翻译流程（`scripts/i18n.mjs`）

词典是 2900+ 条 key，人工逐条翻不现实，所以留了一条可复现的流水线：

```bash
# 1) 把英文词典切成批次（每批 400 条），产出 .i18n-work/src/en/batch-NN.json
node scripts/i18n.mjs split --src en --size 400 --out .i18n-work
#    繁体从简体转写：node scripts/i18n.mjs split --src zh --size 400 --out .i18n-work

# 2) 逐批翻译，结果写成 .i18n-work/out/<locale>/batch-NN.json
#    （每批一个 JSON 对象，key 与源批次完全一致；由 AI 代理 / 翻译服务产出）

# 3) 合并 + 校验 + 生成 src/i18n/<locale>.ts
node scripts/i18n.mjs merge --out .i18n-work

# 4) 结构一致性检查（CI 用；也等价于 pnpm test 里的 locales.test.ts）
node scripts/i18n.mjs check
```

`merge` 会报告每种语言的 `translated / missing / extra / empty / placeholder`，
缺的条目回落到源语言（英文；`zh-TW` 回落简体），所以词典永远可以分步补。

翻译约定（写进批次 prompt 里）：

- `{name}` `{n}` `{count}` `{size}` 这类占位原样保留（可以移动位置，不能翻译花括号里的名字）。
- 产品名、协议名、模型 id、文件名、命令、路径、ISO 码不翻译：`AI Cut`、`MCP`、`OFX`、`ONNX`、
  `CUDA`、`Docker`、`ffmpeg`、`ProRes`、`sd.cpp`、`H.264`……
- 按钮用祈使/名词短语，提示用一句话，长度尽量贴近原文；不额外解释、不加感叹号。
- 目标语言自己的排版规则：`日本語` 用「」、法语用 “” 和非断行空格、阿拉伯语用 `، ؛ ؟`。

## README

- 10 个 `README*.md` 结构必须一致：标题层级、代码块数量、表格、图片 `src` 都一样，只翻正文。
- 顶部语言导航由 `node scripts/readme-nav.mjs` 统一重写；`--check` 只检查不写，并且会顺手比对
  每份 README 的 `##` / `###` / 代码块 / 表格 / 列表数量是否和英文版一致。
- `pnpm i18n:check` = 词典一致性 + README 导航与结构检查，提交前跑一次。
- `MODELS.md` / `docs/**` 目前只有英文/中文，不参与多语言。

## 已知边界

- **内核错误文案没有翻译**。Rust 宿主（`crates/daemon` / `src-tauri`）和部分领域代码抛的错误
  （例如 `未选择模型`、`片段不存在：<id>`）会原样出现在 toast 里——它们同时是 MCP 工具返回给
  代理的错误信息，改文案会动到协议层，所以暂不处理。界面自己的文案（按钮、标签、提示、
  对话框）全部走词典。
- **词典是同步静态引入的**（`./translate` 只带 zh / en，其余 8 门由 `./index` 注册）。翻译在
  语言切换时立即生效，不需要重新加载；代价是每门语言约 180–235 KB 源码（gzip 后 40–60 KB），
  十门语言合计让前端 bundle 大约多 1.5 MB。桌面应用可以接受；如果将来拆到网页端按需加载，
  把 `registerDictionary` 换成动态 import 即可，`t()` 的回退链会保证加载期间仍显示英文。
- 字体：界面用系统字体渲染中日韩与阿拉伯语（`tailwind.config.js` 的 `fontFamily.sans` 里按
  `PingFang SC` / `Noto Sans *` 逐字形回退）。没有随包分发 CJK / 阿拉伯字体。
- RTL 是**布局级**支持：`dir="rtl"` 翻转 flex 顺序与逻辑方向的 CSS；少数绝对定位的浮层
  （画布小地图、缩放手柄）在阿拉伯语下位置仍按 LTR 计算，属于已知的小瑕疵。
