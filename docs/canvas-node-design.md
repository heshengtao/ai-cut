# 画布节点设计约束（强制）

> 状态：**生效**，适用于内置节点与插件节点。
> 相关实现：`src/core/board/registry.ts`（端口 / 卡片）、`src/core/board/dataTypes.ts`（类型）、
> `src/composables/useBoardRun.ts`（读取与产物）、`src/components/board/BoardNode.vue`（卡片 UI）、
> `src/components/workspace/panes/BoardInspectorPane.vue`（检查器）。

画布节点不是「一张表单」，而是**一个干净的卡片 + 一个信息更全的检查器**。下面五条是红线。

---

## 1. 节点 UI 上永远只有一进一出两个点

- 卡片左右各一个 `Handle`（`in` / `out`），**不要**按逻辑端口长出多个锚点。
- 逻辑端口（`portsOf()` 返回的 inputs / outputs）只用于类型判定和检查器，不进卡片。
- 一次连线在画布上只是一根线；它实际走哪个逻辑端口，记录在 `edge.sourcePort` / `edge.targetPort` 上。

理由：多锚点会让画布迅速变成面条，也会让「复制节点 / 重排节点」变得不可能。

## 2. 输入在**检查器**里选择

- 目标节点的检查器「输入」区列出上游可用的输出，用户在这里选择这一路输入接哪个输出。
- 端口声明 `max > 1` 时支持**多选**，顺序就是运行时读取顺序（参考图、多路音频都靠这个顺序）。
- 输出侧不做任何选择：不在输出节点上放「这条线走哪一路」的下拉。

## 3. 输出端点发布**它所有能输出的值**

- 节点可以同时产出多个值（例如循环开始 = `item` + `index`，循环结束 = `out1…outN`，
  输入 / 显示 = 当前值 + 整组数组），这些值都由同一个输出端点发布。
- 下游节点在**自己的**输入列表里随时取用（第 2 条）；`edge.sourcePort`（检查器里选的那一路）优先，
  只有旧连线没有可用端口时才回落到类型匹配。
- 不要为了「多个输出」在输出侧新增第二个锚点，也不要让用户在输出节点上选路。

例外（2026-11-22）：显示节点（`display.*`）的输入是**复合端口**——一个 `in` 端口
可接多个上游，并优先读取上游发布的整组数组。因此显示节点的读取不按
`edge.sourcePort` 单路取；要挑单张还是整组，改在显示节点的**输出**连线里选。

## 4. 有实时 / 最终 / 多个产物时，挂在卡片下方

- 节点运行中或运行后有实时输出、最终产物、或一次产出多个结果时，在卡片**下方**放一个可展开的
  附件组件（模型节点的输出附件卡、显示 / 输入节点的牌堆胶囊都是这个模式）。
- 附件里显示实时 / 最终结果，并支持在多个产物之间切换。
- 附件不要挤进卡片主体：卡片是设置，附件是结果。

## 5. 卡片尽量填满、只留最重要的属性

- 卡片把节点空间用满、只放最关键的一两个属性；「高级选项、输入选择、新建输入、槽位数量」
  这类都放检查器。
- 目标：画布干净、心智负担低；也意味着**大改一个节点的结构时不需要重新连线**
  （连线挂在唯一的一进一出口上，端口重组不影响图）。


## 工作流开始 / 结束 / 嵌入节点

这三个节点不例外，仍是一进一出 + 检查器表达逻辑端口：

- **工作流开始**：没有输入锚点；每个签名输入是一个**逻辑输出端口**（行 id = 端口 id），
  卡片只列「名称 + 类型 + 是否已发布」，增删改在检查器。
- **工作流结束**：没有输出锚点；每个签名输出是一个**逻辑输入端口**，检查器里每行选一个
  上游来源（和循环结束的槽位完全同一种交互：行 = 来源下拉 + 删除 + 「新建输入」）。
- **嵌入工作流**：一进一出；签名输入是逻辑输入端口（检查器里逐行选来源），签名输出是
  值端口（`out-<行 id>`），卡片只显示目标名称与签名。

推论：

- 签名行 id 必须稳定（改名不移动连线），删除行时剪掉挂在该端口上的连线。
- 端口的 `labelKey` 不够用：用户命名的端口用 `BoardPortSpec.label`，UI 优先它。
- 目标工作流的端口用 `data.ports` 快照（插件节点同一机制），目标被删也保留连线。

## 落地检查清单（改画布前过一遍）

- [ ] 卡片模板里没有第二个 `Handle`。
- [ ] 新端口都写在 `portsOf()` / 节点定义里，检查器能选到。
- [ ] 多值输入用 `max` 表达，检查器多选 + 顺序可调。
- [ ] 多个输出由同一端口发布，值写进 `data.values` / `outputText` / `assetId`，不在输出侧加选择。
- [ ] 有产物就考虑附件卡 / 牌堆胶囊，不要塞进卡片。
- [ ] 卡片上只留必要属性，其余进检查器。
- [ ] 插件节点同样遵守；`docs/plugins.md` 的示例不要出现多锚点或输出侧选路。

## 常见反例

- 给 `loop.start` 的 `item` / `index` 各放一个输出锚点，或给 `loop.end` 的每个槽位放一个输出锚点。
- 在输出节点上放「输出连线」下拉，让用户改这条线走哪一路。
- 把「新建输入」「槽位数量」做成卡片上的参数输入框。
- 把实时文本直接铺在模型卡片里，而不是放进下方附件卡。
